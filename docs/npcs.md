# NPC friends: talking, wandering, sidekicks

Code: `src/people/` (`talk.js` conversations and replies, `item-questions.js`,
`speech-bubbles.js`, `wandering.js`, `sidekick.js`, `draw-people.js`,
`characters.js`, `sprites.js`), `src/features/boss/fight-sidekick.js`,
`/api/npc-reply` in `server.js`, and the PubNub Function in `pubnub/`.

A map JSON may also have an `npcs` array. Each entry places one of the
`characters` (from `src/people/characters.js`) on the map; the player's own character is
hidden. Walk up and press **T** (or tap them) to talk: the player types a line,
it pops out of their mouth as a speech bubble, then the NPC replies.
```json
{ "id": "red_scout", "character": "Red Scout",   // must match a characters[].name
  "px": 0.63, "py": 0.78,                          // FEET position, fractions of the image
  "personality": "Free text that shapes how they talk." }
```
Replies come from Claude Haiku (`claude-haiku-5-5`, thinking off, effort low,
`max_tokens` 100). Only the player's latest line is sent, never the history.
`fetchNpcReply` (`src/people/talk.js`) tries, in order:
1. item questions (keyword matching, below), which never reach Claude;
2. the **PubNub Function** `pubnub/npc-function.js` when `NPC_FUNCTION_URL` in
   `src/people/talk.js` is set (it is), except on localhost
   (`NPC_ON_LOCALHOST`: `npm run dev` / `npm test` use step 3 instead). This is for static hosting: the API key is in
   the PubNub Vault, with spending caps in the KV store ($3/UTC day for
   everyone, $0.25/UTC hour per browser player id, `npcPlayerId()`). The
   browser sends only `npcId`, `here` (map path), `pid`, `playerName`,
   `sidekick`, `message`. The Function holds the NPC personas, generated by
   `npm run build:npc` (`tools/build-npc-function.js`). **Re-run it and
   re-paste the Function whenever an NPC, map name or hotspot names change.**
   Setup: [pubnub/README.md](../pubnub/README.md);
3. otherwise the dev server's `POST /api/npc-reply` in `server.js` (needs
   `npm install` and `ANTHROPIC_API_KEY`);
4. `localNpcReply()` if neither answers (not set up, out of usage, offline,
   refusal). After a "limit"/"unconfigured"/network failure the browser stays
   local for `NPC_LIMIT_BACKOFF_MS` (5 min).
Conversations live in memory only.

**Item questions** ("where is the sword?", "have you seen the 🪙?") never go to
Claude. `itemQuestionReply()` in `src/people/item-questions.js` (checked first in
`fetchNpcReply`) uses plain keyword matching: if the line looks like a question
or search (`ITEM_QUESTION_RE`) and names an item by a word of its name or its
emoji (`itemsMentioned`, roughly plural-insensitive), the NPC says where it is
right now on the maps of the level you're on (`crawlMapConfigs` +
`worldItemsFor`, narrowed by `levelMapPaths` in `src/world/maps.js`): hotspots,
kitchen `source`/`shop` stations, or your own backpack. A level is its main map
(the first camp's, or one a `passage` leads to) plus the rooms you can walk to
from it through doors, so in the Second Camp you only hear about the Second
Camp (and the bank, which both camps share). An item that's only on another
level gets "haven't seen any". If nobody's left a sword anywhere, it drops one
first (`findOrDropSword`), and says where only if that's on this level. Lines that don't name an item
go to Claude / `localNpcReply()` as before.

**Wandering.** Camper NPCs stroll around their `px`/`py` spot (within
`NPC_WANDER_RX`/`RY`; `"wander": false` keeps one still). Critters stay put.
Where they're headed comes from the clock (`Date.now()`) and their id
(`wanderTarget`), so every computer in a multiplayer world sees them in the
same place without sending anything. They stop when you're close, so they're
easy to talk to. Their live positions are in `npcRt` (`npcPos()` reads them).

**Sidekicks.** Talking to a camper NPC shows a **🤝 Be my sidekick!** button in
the talk bar. A sidekick (`sidekick` in `src/people/wandering.js`, in memory only) follows
your trail while you walk, settles beside you when you stop, and comes
through doors with you (`placeSidekickBeside` in `switchMap`). They're
talkable as usual. The same button then reads **👋 You can go home**. Your
sidekick also fights the Blob with you (see the boss section). When the fight
ends, or you send them home, they say goodbye and walk home: across the map if
it's their own map, otherwise out the door that leads home (`npcLeavers`,
`exitTowards`), and then they wander there again. Claude is told when an NPC is
your sidekick (`sidekick` in both NPC endpoints).

**Critter NPCs** use an `emoji` instead of a `character` and are drawn as that
emoji (bobbing, squishing while they talk). Example: Sir Ribbit, the frog in
the broken toilet (`assets/bathroom_stall_2.json`).
```json
{ "id": "toilet_frog", "name": "Sir Ribbit", "emoji": "🐸", "color": "#2e7d32",
  "size": 0.1,                                   // height as a fraction of the map
  "px": 0.5, "py": 0.575,                        // FEET position
  "what": "a little talking frog who lives in the broken toilet",  // tells Claude what they are
  "personality": "...",
  "localReplies": { "hello": [], "bye": [], "question": [], "any": [] } }  // offline lines; {name} = player
```
